# 5. P0-NATIVE-01 — PREFLIGHT AND LAUNCH ELIGIBILITY DISAGREE

**Severity:** P0 / Native execution correctness  
**Finding:** Confirmed by source inspection.

Files:

```text
scripts/native/native_test_adapter.gd:953–971
scripts/native/native_test_adapter.gd:1956–2005

scripts/native/native_experiment_runner.gd:691–708
scripts/native/native_experiment_runner.gd:729–749
scripts/native/native_experiment_runner.gd:811–826
scripts/native/native_experiment_runner.gd:1169–1190
```

## Problem

`NativeTestAdapter.diagnose_config_path_compatibility()` correctly identifies:

```text
CONFIG_REQUIRES_ROOTDIR_PLACEMENT
```

when SHAMAN config is staged outside BZ2R.

But `preflight_experiment()` calculates launch readiness using:

```gdscript
var structurally_valid := issues.is_empty()
var launch_ready := structurally_valid and blockers.is_empty()
```

The config compatibility diagnostic is stored in the generated launch command, but is not consistently promoted into a mandatory launch blocker.

Separately, `NativeExperimentRunner.preflight()` stores:

```gdscript
var preflight_passed := bool(
    pre.get("structurally_valid", false)
)
```

and:

```gdscript
"launch_eligible": preflight_passed and pkg_ok
```

The function also returns:

```gdscript
"launch_eligible": preflight_passed
"launch_ready": bool(pre.get("launch_ready", false))
```

Thus:

```text
STRUCTURALLY_VALID = true
LAUNCH_READY      = false
LAUNCH_ELIGIBLE   = true
```

can occur.

That distinction is currently not enforced consistently by `stage()` and `launch()`.

## Why this matters

T-60 established that external `/config` paths are not usable in the tested BZCC launch mode.

Yet the runner can still store a launch-eligible session whose command references such a path.

With authenticated Steam, a native launch may be attempted even though the configuration is already known to be incompatible.

## Required fix

Introduce independent gates:

```text
STRUCTURALLY_VALID
RESOURCE_CLOSURE_VALID
STAGE_ELIGIBLE
CONFIG_COMPATIBLE
EXECUTION_ENVIRONMENT_READY
LAUNCH_ELIGIBLE
```

Define:

```text
STAGE_ELIGIBLE:
Valid scenario and resource closure, even if Steam isn't available.

LAUNCH_ELIGIBLE:
Valid stage + verified config compatibility + supported execution route.
```

Manual handoff may be prepared for a structurally valid stage.

**Actual game launch must not proceed while `CONFIG_REQUIRES_ROOTDIR_PLACEMENT` remains unresolved.**

## Acceptance

### Scenario A

```text
Valid BZN/Lua
Valid closure
External /config
Authenticated Steam
```

Expected:

```text
STRUCTURALLY_VALID=true
STAGE_ELIGIBLE=true
LAUNCH_ELIGIBLE=false
CONFIG_REQUIRES_ROOTDIR_PLACEMENT
```

### Scenario B

Known compatible config placement with all other gates satisfied.

Expected:

```text
LAUNCH_ELIGIBLE=true
```

### Scenario C

Steam unavailable, valid stage.

Expected:

```text
STAGE_ELIGIBLE=true
AWAITING_OPERATOR
```

No actual process launch.

Add integration regressions proving the distinction.

```gdscript
sim.advance(dt)
```

- Damage over time.

The core CombatScenario tests call `advance()` directly, so they do not prove the Weapons Lab uses it.

Make `CombatScenario` the single simulation clock owner for active combat.

Replace independent Weapons Lab stepping with coordinated scenario stepping.

Unify:

```text
Projectile simulation
Combat actor ticks
Reload timers
Damage over time
Target effects
Timeline events
Replay
```

All must use the same deterministic simulation clock.

### Important

Do not tick actor state twice.

Audit every caller of `sim.advance()` before refactoring.

## Acceptance

3. Pause simulation.

# 9. P1-SIM-03 — COMBAT REPLAY DOES NOT RESTORE THE COMPLETE INITIAL SCENE

**Finding:** Confirmed by source inspection.

Files:

```text

scripts/sim/combat_scenario.gd:249–280
```

`CombatActorState.snapshot()` records:

```text
position
velocity
yaw_rad
radius
```

But `restore_snapshot()` restores health, shield, ammo, energy and active effects without restoring these spatial fields.

It also does not restore the full hitbox representation.

## Consequence

After a target moves or rotates, calling:

```gdscript
reset("ALL")
```

does not necessarily restore its original position, velocity or collision geometry.

`replay_deterministic()` consequently may use a different scene state than the original experiment.

## Additional replay limitation

`shot_history` records:

```text
origin
direction
target_position
shooter_velocity
weapon_name
ordnance_name
ammo_spent
energy_spent
time
```

But replay uses the *current* WeaponProfile and externally supplied obstacles rather than an immutable snapshot of every historical shot's relevant configuration.

This limits replay across:

- ODF edits.
- Weapon changes.
- Target movement.
- Obstacle changes.
- Multiple actors.

## Required fix

Introduce an immutable CombatReplaySnapshot containing:

```text
Scenario ID
Simulation seed
Initial actor states
Actor transforms
Hitboxes
Obstacles
Selected ODF revisions
Weapon profiles
Projectile parameters
Timeline input events
Shot commands
```

Restore the complete initial scene before replay.

Avoid overwriting the current user's scenario unexpectedly when replaying an old experiment.

Prefer a sandboxed replay instance or provide an explicit destructive reset policy.

## Acceptance

```text
Target starts at X=0
Shot 1
Move target to X=20
Shot 2
Replay
```

The replay must reproduce the intended historical sequence, including the move.

After changing the ODF, replaying the old run must still use the old captured revision.

A new run may use the newly edited ODF.

This distinction is essential for meaningful A/B comparisons.

# 10. P1-SIM-04 — RECONFIGURATION OVERWRITES THE REPLAY BASELINE

```text

```

- Reload state.
- Active status effects.

```text

UPDATE EFFECTIVE ODF PARAMETERS
CHANGE WEAPON
```

A routine parameter refresh must not silently redefine the initial combat state.

When changing weapon profile during an ongoing experiment:

- Preserve actor resources where appropriate.
- Preserve active effects.
- Preserve elapsed cooldown when semantically applicable.
- Record the profile change as a timeline event.
- Keep the original replay baseline intact.

## Acceptance

```text
Initial ammo: 30
Fire → 20
Edit weapon parameter
Fire → 10
Reset to initial
```

Expected:

```text
Ammo restored to 30
```

not to 20.

Also verify that active effects and shield state follow the selected preservation policy.

Keep evidence artifacts separate from disposable stage files.
